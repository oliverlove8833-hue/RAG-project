# 노동자 근로기준법 안내 도우미

> 상명 AI Training · 팀 프로젝트 1 (2·3·4일차)
> RAG · Text2SQL · LangGraph 기반 데이터 조회 에이전트

법을 잘 모르는 노동자가 일상적인 말로 물어보면, 고용노동부 공식 가이드북에서 근거를 찾아 쉬운 말로 답해주는 상담 도우미입니다.

```
"알바인데 임금명세서를 안 주는데 원래 주는 건가요?"
  → 사장님은 임금명세서를 교부할 의무가 있습니다. 위반 시 500만원 이하 과태료...
     (출처: 2026년 노무관리 가이드북, 44쪽)
```

---

## 1. 문제 정의

근로기준법 정보는 이미 공개돼 있지만 노동자가 쓰기 어렵습니다.

| 문제 | 해결 방법 |
|---|---|
| 270쪽 PDF에서 내 상황을 못 찾음 | 의미 기반 검색(RAG)으로 관련 페이지 자동 검색 |
| 법률 용어가 어려움 | LLM이 쉬운 말로 풀어서 설명 |
| **문서가 사업주(사장님) 대상으로 쓰임** | 프롬프트로 노동자 관점 전환 |
| 챗봇이 그럴듯한 거짓말을 함 | 문서에 없으면 "없다"고 답하도록 강제 + 출처·페이지 표시 |
| "몇 쪽에 뭐가 있는지" 같은 질문은 검색이 비효율적 | 목차·서식을 테이블로 만들어 SQL로 조회 |

세 번째가 이 프로젝트의 핵심 설계 포인트입니다. 원문은 `"사용자(사업주)는 ~하여야 한다"` 형식이지만, 사업주의 의무는 곧 노동자의 권리이므로 답변 단계에서 관점을 뒤집습니다.

---

## 2. 사용 데이터

같은 가이드북을 **본문은 문서로, 목차·서식은 테이블로** 나눠서 씁니다.

### 2-1. 문서 데이터 — 2일차 RAG

**[고용노동부] 2026년 노무관리 가이드북** (`[고용노동부] 2026년 노무관리 가이드북__.pdf`)

| 항목 | 값 |
|---|---|
| 발행 | 고용노동부 (2026) |
| 전체 페이지 | 270쪽 |
| Parent 문서 (내용 있는 페이지) | 264개 |
| Child chunk (400자 / overlap 50) | 1,128개 |
| 평균 페이지 길이 | 1,159자 |
| 텍스트 레이어 | 정상 (OCR 불필요) |

선정 이유

- 근로기준법 전 영역(16개 장)을 실무 기준으로 정리한 **정부 공식 문서** — 출처 신뢰성 확보
- 항목마다 **관련 법조문 · 과태료/벌칙 · Q&A 사례**가 붙어 있어 답변 근거로 바로 쓰임
- 장·절 구조가 명확해 **메타데이터 필터링**을 붙이기 좋음
- 인쇄 쪽번호와 PDF 페이지 번호가 일치해 출처 표시가 정확함

### 2-2. 테이블 데이터 — 3일차 Text2SQL

같은 가이드북의 목차와 서식 목록을 3개 테이블로 정규화했습니다.

```
categories (17행)  ──<  topics (37행)  ──<  forms (22행)
   장 구조              절 · 담당부서            서식
```

| 테이블 | 내용 | 주요 컬럼 |
|---|---|---|
| `categories` | 가이드북 전체 + 16개 장의 계층 구조 | `category_id`, `category_name`, `parent_category_id`, `category_level`, `category_code` |
| `topics` | 절 단위 항목과 소관 부서 | `topic_id`, `category_id`, `topic_code`, `page_start`, `related_law`, `dept_name`, `dept_phone` |
| `forms` | 표준근로계약서 등 서식 목록 | `form_id`, `form_name`, `related_topic_code`, `page`, `form_type` |

`categories → topics → forms`로 이어지는 외래키 구조라 JOIN 질의가 가능합니다. 문서와 테이블이 **같은 페이지 번호 체계**를 공유하므로, SQL로 찾은 쪽수를 RAG 검색에 그대로 넘길 수 있습니다.

## 3. 테스트 질문

**RAG — 내용을 묻는 질문**

```python
questions = [
    "알바생 주휴수당 기준 알려줘",
    "알바생 근로시간과 휴게시간 규정에 대해 알려줘",
    "알바생 최저임금과 관련된 법규에 대해 알려줘",
]
```

**Text2SQL — 목록·위치를 묻는 질문**

```python
questions = [
    "표준근로계약서 서식은 몇 쪽에 있어?",
    "장별로 항목이 몇 개씩 있는지 알려줘",
    "기간제법 관련 항목은 뭐가 있어?",
    "근로기준정책과가 담당하는 항목 전부 보여줘",
]
```

## 4. PDF + DB 활용 방안 확장
### 시스템 설계 — 질문 유형에 따른 데이터 조회 분기

기존 RAG 프로젝트의 PDF 문서와 새롭게 구축한 DB를 함께 활용하여, 사용자의 질문 유형에 따라 적절한 데이터에서 정보를 조회하는 시스템을 설계한다.

### 4-1. PDF 활용

근로기준법, 주휴수당, 임금체불 등 노무 관련 제도나 대응 방법에 대한 **상담성 질문**에 활용한다.

- "주휴수당을 받을 수 있는 조건이 무엇인가요?"
- "임금을 받지 못했을 때 어떻게 해야 하나요?"

### 4-2. DB 활용

PDF의 설명만으로 해결하기 어렵거나 추가적인 도움이 필요한 경우, 담당 기관·부서의 **전화번호, 주소, 담당 업무 등 정확한 정보 조회**에 활용한다.

- "임금체불은 어디에 문의해야 하나요?"
- "노동 상담을 받을 수 있는 기관의 전화번호를 알려주세요."

### 4-3. PDF + DB 함께 활용

사용자가 문제에 대한 **설명과 실제 해결 방법을 동시에** 필요로 하는 경우 두 데이터를 함께 활용한다.

- "아르바이트비를 못 받았는데 어떻게 해야 하고 어디에 문의해야 하나요?"
  - **PDF** → 임금체불에 대한 설명과 대응 방법 제공
  - **DB** → 관련 담당 기관, 전화번호, 주소 등의 정보 제공

## 5. LangGraph 에이전트 워크플로우 — 4일차

4장에서 설계한 분기를 LangGraph 그래프로 구현했습니다. 질문 의도를 분류해 **PDF 경로 / DB 경로 / 두 경로 병렬** 중 하나를 자동으로 선택합니다.

### 5-1. 의도 분류

`classify_intent` 노드가 질문을 4가지로 나눕니다. 4장의 활용 방안과 1:1로 대응합니다.

| intent | 대응 | 질문 예시 |
|---|---|---|
| `general` | — | "안녕하세요", "뭘 할 수 있어?" |
| `labor_consult` | 4-1 PDF | "주휴수당 받는 조건이 뭐야?" |
| `database` | 4-2 DB | "표준근로계약서 서식은 몇 쪽에 있어?" |
| `hybrid` | 4-3 PDF + DB | "알바비를 못 받았는데 어떻게 하고 어디 문의해?" |

### 5-2. 그래프 구조

![LangGraph 워크플로우](langgraph_workflow.png)

`classify_intent`에서 4갈래로 나뉘고, 어느 경로를 타든 `combine_context → generate_answer → validate_answer`로 합류합니다. PDF 경로(초록)와 DB 경로(빨강)는 각자 검증 단계를 두고 실패 시 재시도하며, `hybrid`는 두 경로를 동시에 실행한 뒤 문맥을 합칩니다.
